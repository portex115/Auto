# Автопостер рилсов в Instagram и TikTok

Скрипт сам публикует рилсы в Instagram и TikTok. Работает на серверах GitHub, твой компьютер для этого не нужен.

Три очереди (подробнее в разделе «Отдельные очереди Instagram и TikTok»):

| Папка | Куда уходят ролики |
|---|---|
| `queue-instagram/` | только в аккаунты Instagram |
| `queue-tiktok/` | только в TikTok |
| `queue/` | общая: каждый ролик во все аккаунты обеих сетей (как раньше) |

## Как это устроено

Одно длинное видео = одна папка = рилсы на один день.

```
queue/
  001_podcast/          ← день 1
    01.mp4  01.txt  01.jpg
    02.mp4  02.txt
    ...
  002_interview/        ← день 2
    01.mp4  01.txt  01.jpg
    ...
```

- Каждый день берётся **следующая папка по алфавиту** (поэтому нумеруй: `001_`, `002_`, …).
- Её рилсы выходят **равномерно с 10:00 до 22:00 по Москве**. Например, 7 рилсов: 10, 12, 14, 16, 18, 20, 22 часов; 6 рилсов: примерно каждые 2,5 часа.
- Внутри папки рилсы идут по алфавиту: `01`, `02`, …
- Когда папка опубликована целиком, она переезжает в `posted/`. Ссылки на рилсы пишутся в `state.json`.
- Если папки в очереди закончились, скрипт просто ждёт новые.

Файлы для каждого рилса (имена совпадают, отличается только расширение):

| Файл | Что это | Обязательно |
|---|---|---|
| `01.mp4` | видео (вертикальное 9:16, до 15 минут) | да |
| `01.txt` | описание к рилсу, весь текст как есть, с хэштегами | нет |
| `01.jpg` | обложка (лучше 1080×1920) | нет |

Без обложки берётся кадр с 1-й секунды. Без `.txt` подпись будет пустой (или `default_text` из настроек).

## Как загрузить папку

На сайте GitHub: открой `queue/` → **Add file → Upload files** → перетащи всю папку целиком → **Commit changes**.
Через сайт можно загрузить файл до 25 МБ. Крупнее нужно сжать или загрузить через GitHub Desktop (до 100 МБ).

Загружай папку **до 10:00 МСК** дня публикации. Если загрузить позже, рилсы распределятся на остаток дня.

## Настройка (один раз)

1. Репозиторий публичный: так Instagram может забрать обложку по ссылке.
2. **Settings → Secrets and variables → Actions → New repository secret**, добавь:
   - `IG_TOKEN`: токен Instagram
   - `IG_USER_ID`: `17841431768361264`
   - `GH_PAT` (для автопродления токена): Fine-grained token на github.com/settings/tokens
     с доступом только к этому репозиторию и правом **Secrets: Read and write**.
3. Вкладка **Actions** → «Публикация рилсов» → **Run workflow** → `check`. Должно написать «Токен работает».

Посмотреть, какие подписи и в какое время выйдут, без публикации: Run workflow → `dry-run`.

## Настройки в `config.json`

- `day_start`, `day_end`: окно публикаций (по умолчанию `10:00` и `22:00`)
- `timezone`: часовой пояс (по умолчанию `Europe/Moscow`)
- `hashtags`: хэштеги, которые добавляются к каждому рилсу, например `"#dayzero #reels"`
- `default_text`: подпись для видео без `.txt`
- `thumb_offset_ms`: с какой миллисекунды брать кадр для обложки, если нет `.jpg`
- `share_to_feed`: показывать ли рилс в сетке профиля

## Токен

Токены Instagram Login живут 60 дней. Workflow «Продление токена» раз в неделю продлевает токены **всех** аккаунтов
Instagram из `config.json` и, если задан `GH_PAT`, сам сохраняет новые в их секреты. Без `GH_PAT` продлённый токен придётся
вставлять вручную. Бессрочный токен системного пользователя (EAA) продлевать не нужно.

## Добавить аккаунт кнопкой

В виджете (4.1+): раздел TikTok или Instagram → **«+ аккаунт»** → войти в соцсеть → «Сохранить аккаунт». Токен сам уходит
в секрет GitHub, аккаунт в `config.json`. Подготовка, несколько аккаунтов подряд и копия для друга со своими аккаунтами:
[docs/accounts-setup.md](docs/accounts-setup.md).

## Несколько аккаунтов Instagram

Очередь одна. Есть два формата папки дня (можно смешивать в одной папке):

- **Плоская папка**: каждый рилс выходит **во все аккаунты** в одно и то же время (описания по блокам `REELS CAPTION (Instagram @имя):`, см. ниже).
- **Папка с подпапками по аккаунтам**: у каждого аккаунта свои рилсы, описания и обложки. Подпапка называется как аккаунт (`dayzerorules`, `rulezerosurvivel`, `survivelzerorule`; можно с `@`), аккаунт получает только рилсы из своей подпапки.

```
queue/
  003_Night-Shift/               ← один день
    dayzerorules/
      short-1-x.mp4  short-1-x.txt  cover-1.jpg
      ... (7 рилсов)
    rulezerosurvivel/
      short-1-y.mp4  short-1-y.txt  cover-1.jpg
      ... (7 других рилсов)
    survivelzerorule/
      ... (ещё 7 своих)
```

Каждый аккаунт публикует свои рилсы равномерно с 10:00 до 22:00, независимо от других (7 рилсов: 10, 12, …, 22 часов). В `.txt` внутри подпапки пишется обычный блок `REELS CAPTION (Instagram):` и `COVER: файл.jpg`.
Подпапка с именем, которого нет среди аккаунтов, пропускается (в логе будет строка об этом). Папка уходит в `posted/`, когда опубликованы рилсы всех подпапок. Промт для проекта, который готовит такие папки: `prompt-for-video-project.md`.

### Убрать папку из очереди

- В виджете: корзина справа в строке папки → подтвердить. Папка удаляется из репозитория одним коммитом (в истории git файлы остаются).
- Вручную: удали папку `queue/NNN_имя` на сайте GitHub или командой `python autoposter.py remove NNN_имя` (при локальном запуске).

Невышедшие рилсы удалённой папки больше не публикуются, уже вышедшие в Instagram остаются.

### Общая очередь для плоской папки

Рилс из плоской папки выходит **во все аккаунты** в одно и то же время. Папка уходит в `posted/`, когда рилс опубликован везде.

1. Для каждого нового аккаунта создай токен (как для первого) и добавь два секрета в GitHub: `IG_TOKEN_<ИМЯ>` (ID аккаунта не секрет, его можно указать прямо в config.json полем `user_id`).
2. Допиши аккаунт в `config.json`:

```json
"accounts": [
  {"name": "dayzerorules", "token_env": "IG_TOKEN", "user_id_env": "IG_USER_ID"},
  {"name": "second", "token_env": "IG_TOKEN_SECOND", "user_id_env": "IG_USER_ID_SECOND"}
]
```

   Пока секрета нет, аккаунт просто пропускается.
3. В `.txt` рилса для каждого аккаунта пиши свой блок, имя аккаунта в заголовке:

```
REELS CAPTION (Instagram @dayzerorules):
Подпись для первого аккаунта #tag

REELS CAPTION (Instagram @second):
Подпись для второго аккаунта #tag
```

   Если блок с именем аккаунта не найден, берётся обычный `REELS CAPTION (Instagram):`.
   Свою обложку для аккаунта задай строкой `COVER (Instagram @имя): файл.jpg` (файл лежит в той же папке). Без такой строки берётся общая `COVER:`.
4. Проверь: Actions → Run workflow → `check` (проверит токены всех аккаунтов) и `dry-run` (покажет подписи для каждого).

## Если что-то пошло не так

Actions → открой красный запуск → там текст ошибки. Рилс, который не удалось опубликовать 3 раза подряд,
пропускается и записывается в `state.json` → `skipped`. Чтобы попробовать снова, удали его оттуда.
GitHub запускает задачи по расписанию с опозданием до 5–30 минут, это нормально.

## Отдельные очереди Instagram и TikTok

У каждой очереди своё расписание: своя папка дня и свой план с `day_start` до `day_end`. Поэтому в один день
может выходить папка из `queue-instagram/` в Instagram и другая папка из `queue-tiktok/` в TikTok.
Внутри очередей всё как раньше: одна папка = рилсы на день, подпапки по аккаунтам, `.txt`, обложки.
Опубликованные папки переезжают в `posted-instagram/` и `posted-tiktok/` (из общей очереди, как раньше, в `posted/`).

- Отдельная очередь TikTok не теряет ролики: если TikTok не принял ролик (лимит черновиков), он переносится на следующий день.
  В общей очереди TikTok, как и раньше, не держит очередь: невышедший за день ролик в TikTok пропускается.
- В истории (`state.json`) ролики отдельных очередей записаны с приставкой: `instagram:017_x/short-1.mp4`, `tiktok:018_y/short-1.mp4`.
- Опубликовать один ролик сейчас: Actions → «Публикация рилсов» → `only` = `tiktok:018_y/short-1.mp4` (или часть имени).
- Убрать папку командой: `python autoposter.py remove tiktok:018_y`.

### Пауза

`"paused": ["tiktok"]` в `config.json` (или кнопка «Пауза» в виджете) останавливает очередь этой сети. Общая очередь
`queue/` стоит, пока на паузе любая сеть. После снятия паузы остаток дня распределяется заново с текущего момента,
чтобы ролики не вышли все сразу.

## Тексты и комментарии, которые прикрепляются сами

В `config.json` (удобнее в виджете: кнопка «Тексты» в разделе сети):

```json
"texts": {
  "instagram": {"caption": "", "footer": "Full story on YouTube", "hashtags": "#dayzerorules #survival",
                "comment": "Rule #1 is in the full video", "use_pinned_comment": false},
  "tiktok":    {"hashtags": "#fyp #survival"}
}
```

- `caption`: подпись, если у видео нет своего `.txt`;
- `footer`: строка, которая добавляется в конец каждой подписи;
- `hashtags`: хэштеги этой сети (вместо общих `hashtags`);
- `comment`: первый комментарий под рилсом, автопостер пишет его сразу после публикации (**только Instagram**:
  TikTok не разрешает программам оставлять комментарии);
- `use_pinned_comment`: брать комментарий из раздела `PINNED COMMENT:` в `.txt`.

На одну папку: файл `texts.json` в папке дня (или в подпапке аккаунта) с теми же ключами. Плоские ключи действуют на все сети,
ключи `"instagram": {...}` и `"tiktok": {...}` только на свою. Свой комментарий для одного видео: раздел `COMMENT:` в его `.txt`.
Порядок: `.txt` видео → `texts.json` подпапки → `texts.json` папки → настройки сети в `config.json`.

Комментарий требует у токена Instagram разрешение **instagram_manage_comments**. Без него рилс всё равно выходит,
а в `state.json` у рилса пишется `comment_error` (в виджете: «! коммент.»).

## Виджет для Windows

Окно в стиле виджетов Windows 11 со стеклом (акрил). Сверху два раздела: **Instagram** и **TikTok** (Ctrl+1 / Ctrl+2).
В каждом разделе: аккаунты сети и режим, план на сегодня, очередь (свои папки и общие с пометкой «обе сети»), раздел «Готово».

- **Загрузка**: перетащи папку в окно или нажми «+». Перед загрузкой выбери, куда: Instagram, TikTok или обе сети,
  и при желании задай тексты для этой папки. Папка уходит одним коммитом под следующим номером. Лимит на файл 95 МБ.
- **Пауза / Продолжить**: остановить автозалив в этой сети.
- **Тексты**: подпись по умолчанию, хвост подписи, хэштеги, первый комментарий (Instagram). Карандаш у папки: тексты только этой папки.
- **Запустить**: запустить автопостер на GitHub сейчас (выложит то, что уже пора по плану).
- **Молния у ролика**: опубликовать этот ролик сейчас, вне расписания.
- **TikTok**: режим «черновики» (ролик приходит уведомлением в приложение TikTok) или «прямая публикация».
  Для прямой публикации каждый ролик подтверждается на экране, который требует TikTok: превью, название, кто может смотреть
  (только из вариантов TikTok, без значения по умолчанию), комментарии/дуэт/сшивание, раскрытие рекламы, согласие с условиями.
  Неподтверждённый ролик уходит в черновики.
- Корзина у папки: убрать её из очереди.
- **Аккаунты**: точка у ника показывает, работает ли токен. «+ аккаунт» добавляет новый, нажатие на аккаунт:
  «Переподключить» или «Убрать» (см. [docs/accounts-setup.md](docs/accounts-setup.md)).

1. Скачай `ReelsWidget-Setup.exe` со страницы [Releases](../../releases/tag/widget) и запусти (установка без прав администратора).
   Если Windows пишет «неизвестный издатель»: **Подробнее → Выполнить в любом случае**.
   Если браузер блокирует .exe: Ctrl+J → «Сохранить».
2. При первом запуске откроются настройки: вставь токен GitHub.
   github.com/settings/personal-access-tokens → Only select repositories → autopostreels →
   **Contents: Read and write** (обязательно), **Actions: Read and write** (для кнопок «Запустить» и «молния»)
   и **Secrets: Read and write** (для кнопки «+ аккаунт»).
   Токен шифруется средствами Windows (DPAPI).

Ещё: часы (местное время и время расписания), значок в трее (крестик сворачивает в трей), автозапуск вместе с Windows,
закрепление поверх окон, тема, материал окна и сила тонировки. Стекло работает на Windows 11 22H2 и новее.
Виджет собирается сам после каждого изменения в `widget-app/` в ветке main (workflow «Сборка виджета для Windows»).
Тесты: `python -m unittest discover -s tests` и `cd widget-app && npm test` (их же запускает workflow «Тесты»).
История работы: [docs/WORKLOG.md](docs/WORKLOG.md), исправленные баги: [docs/BUGFIXES.md](docs/BUGFIXES.md).

## Reels Studio: нарезки стримов

Отдельное приложение для Windows в `studio-app/`: ищет записи стримов и моменты, делает вертикальные ролики
с субтитрами под несколько каналов и кладёт их в формате этой очереди (`queue/NNN_имя/<аккаунт>/…`).
Установщик: Releases → `studio`. Подробно: [studio-app/README.md](studio-app/README.md).

## TikTok

Рилсы из той же очереди могут уходить и в TikTok (официальный Content Posting API). По умолчанию ролик попадает
в черновики TikTok, и ты публикуешь его одним нажатием в приложении: для этого не нужен аудит TikTok.
Что сделать руками: [docs/tiktok-setup.md](docs/tiktok-setup.md). Тексты для проверки приложения TikTok:
[docs/tiktok-app-review.md](docs/tiktok-app-review.md).
